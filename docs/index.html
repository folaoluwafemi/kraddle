KRADDLE FORMAT / OVERVIEW

Alpha specification

Keep software connected to what it means.

The Kraddle Format is a project-native, database-free structure for recording what software does, what it is for, what it must preserve, and how every part relates.

Why it exists

Software meaning is usually fragmented across source code, tests, product documents, design files, commit history, conversations, and human memory. Kraddle gives those pieces a shared structure that travels with the project.

01

What does it do?

Inputs, outputs, effects, states, and observed behavior.

02

What is it for?

The purpose, capability, or user outcome a unit serves.

03

What must it preserve?

Constraints, contracts, invariants, and experience qualities.

04

How does it relate?

Vertical realization and horizontal collaboration across the system.

Design principles

  1. Project-native.Meaning lives in .kraddle/ and travels with the project.
  2. Database-free.Canonical state, indexes, history, and synchronization are file-native.
  3. Local-first.Every operation works without a network connection.
  4. Evidence-backed.Observed facts, interpretations, and commitments remain distinct.
  5. Compact but recoverable.Normal storage is binary; readable export is always available.

CORE CONCEPTS

Meaning model

Meaning is composed from units, commitments, relationships, evidence, and scopes.

Meaning unitAnything Kraddle can discuss, from a product purpose to a function.
CommitmentWhat a unit does, is for, must preserve, or becomes in use.
RelationshipA typed semantic connection between two units.
EvidenceA source that supports, challenges, or explains meaning.
ScopeThe product, feature, revision, worktree, or alternative where meaning applies.

Meaning is compositional

product purpose
  └── realized_by → capability
        └── realized_by → behavior
              ├── implemented_by → UI component
              └── implemented_by → service
                    └── decomposed_into → function

CORE CONCEPTS

Truth and evidence

Kraddle never turns a plausible interpretation into an accepted truth silently.

observed

Directly present in code, runtime behavior, or user input.

derived

Computed from observations using an explicit rule.

inferred

A plausible interpretation of available evidence.

accepted

Explicitly approved by an actor or trusted policy.

stale

May no longer describe the referenced revision.

!

Extractors write observations. Agents propose interpretations. Neither may silently create accepted commitments.

CORE CONCEPTS

Identity and scope

Meaning survives renamed files, refactored symbols, parallel worktrees, and alternative implementations.

Stable code anchors

repository identity
language
symbol kind
qualified name
signature fingerprint
structural fingerprint
source revision

After each scan, an anchor remap is marked exact, probable, ambiguous, or broken. Commitments never move across an ambiguous remap without confirmation.

FORMAT SPECIFICATION

Directory layout

One canonical `.kraddle/` workspace lives beside the code.

.kraddle/
├── manifest.krd       # identity and format version
├── schema.krd         # vocabulary and relationship types
├── heads.krd          # current causal event heads
├── events/            # immutable event segments
├── objects/           # content-addressed evidence
├── indexes/           # rebuildable file-native indexes
└── local/             # device state; never synchronized
✓
No database layer

No SQL engine, embedded database, graph database, or database service is part of local or cloud storage.

FORMAT SPECIFICATION

Events and history

Immutable events are the canonical history. Current views are projections of that history.

event_id          globally unique 128-bit ID
workspace_id      owning workspace
actor_id          human, device, extractor, or agent
logical_time      causal ordering clock
causal_parents    zero or more event IDs
payload           record operations
schema_version    encoding schema

FORMAT SPECIFICATION

Binary encoding

KRD is a deterministic, framed binary container designed for compactness and forward compatibility.

0–3Magic4B 52 44 00
4Majoruint8
5Minoruint8
6–7Flagsuint16
8–23Workspace IDid128
24–31Header lengthuint64

Frames are length-prefixed and checksummed. Readers can skip unknown optional frames without understanding them.

FORMAT SPECIFICATION

Objects and indexes

Store large evidence once and query connected meaning through disposable file-native indexes.

units.kriRecord ID to latest projected record and event.
edges.kriUnit ID and relationship type to neighboring IDs.
text.kriSearch tokens to matching unit and commitment IDs.
anchors.kriArtifact anchors to meaning unit IDs.
events.kriEvent IDs to segment byte offsets.

OPERATIONS

Extraction

Turn code, documents, tests, and runtime behavior into evidence-backed observations.

Discover→Parse→Analyze→Anchor→Observe→Confirm

OPERATIONS

Synchronization

Replicate immutable event frames and referenced objects without requiring a central service.

  1. Exchange heads.Compare causal event heads and format capabilities.
  2. Transfer gaps.Send missing frames and referenced content-addressed objects.
  3. Verify.Check event identities, causal parents, and checksums.
  4. Project.Update current views and rebuild affected index runs.

REFERENCE

Format invariants

Rules every conforming Kraddle implementation must preserve.

  1. 01

    .kraddle/ is the canonical source of project meaning.

  2. 02

    Canonical and derived storage use no database engine or service.

  3. 03

    Inferred meaning never becomes accepted without an explicit actor or policy.

  4. 04

    Every observation names its source revision and extractor version.

  5. 05

    Conflicting accepted meaning is never silently discarded.

  6. 06

    Indexes are rebuildable and contain no unique meaning.
